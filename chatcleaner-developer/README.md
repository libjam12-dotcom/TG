# Chatcleaner: исходники для доработки инвайтинга

Это отдельная очищенная копия для внешнего разработчика. Производственные учётные записи, базы, сессии, персональные списки, переписка, секреты, история Git и доступ к серверу отсутствуют. Идентификаторы и профили в коде/тестах заменены тестовыми. Личный модуль сообщества владельца заменён пустым адаптером; старый рекламный шаблон исключён. Остальные клиентские подсистемы включены для понимания зависимостей.

## Быстрый запуск

Нужны Python 3.12 и Node.js 20+ (Node нужен для тестов интерфейса). Выполнять из корня распакованного пакета:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r scanner/requirements.txt
.venv/bin/python dev/run.py
```

Открыть http://127.0.0.1:8080/#invite-settings . Порты 8080 и 8787 должны быть свободны. Остановить Ctrl+C. На Windows использовать `.venv\Scripts\python.exe` вместо `.venv/bin/python`.

Локальный адаптер заменяет производственный вход тестовой ролью владельца, проксирует API в backend на 127.0.0.1:8787 и НЕ является сервером авторизации для публикации в интернете. Входной Host и Origin проверяются. Интерфейс и backend слушают только loopback. Не публикуйте порты через туннели и не меняйте bind на 0.0.0.0.

Новая `.local-data/` создаётся только при запуске. Аккаунт не подключён, задания отсутствуют. Исходящий Python-трафик по умолчанию блокируется `dev/sitecustomize.py`, включая DNS вне localhost. Это защита от случайного обращения, а не полноценная песочница. Для изоляции используйте собственную VM/контейнер без доступов владельца. Не запускайте исходники в каталоге с настоящими сессиями.

Для настоящего теста разработчик использует СВОЙ выделенный аккаунт и СВОЮ закрытую группу с согласившимися участниками. После отдельного согласования он может установить `HANDOVER_ALLOW_EXTERNAL=1` перед запуском; тогда блокировка внешней сети снимается. API ID/hash получают самостоятельно через https://my.telegram.org/apps . Никаких общих реквизитов в пакете нет. Восстановление реального аккаунта/сессии из этого пакета невозможно.

## Проверки

```sh
# По умолчанию все проверки без внешней сети:
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=dev:scanner .venv/bin/python -m unittest discover -s scanner/tests
node --test tests/*.test.cjs
# Отдельная регрессия потери RPC-ошибки:
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=dev:scanner .venv/bin/python scanner/tests/test_manual_rpc_regression.py
```

На Windows задайте переменные окружения средствами PowerShell; разделитель PYTHONPATH — `;`.

См. `docs/VERIFICATION.md`: полный backend-набор имеет известные сбои; это не обещание, что вся панель уже исправна. Не включайте сеть для исправления unit-тестов. Они используют временную SQLite и fake Telegram.

## Что читать разработчику

1. `docs/INVITING.md` — схема выполнения, воспроизводимые ошибки и границы вывода.
2. `docs/ACCEPTANCE.md` — критерии готовности и сдачи.
3. `docs/SOURCE-STATUS.md` — локальная копия и отличие от production.
4. `docs/SECURITY.md` — состав передачи и проверка безопасности.
5. `MANIFEST.sha256` — контроль целостности переданного содержимого.

Все изменения сдавать патчем/веткой с тестами. Автоматического deployment нет. Установка на работающий сервер выполняется владельцем после отдельной проверки.
