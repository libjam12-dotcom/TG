# Инвайтинг: задача и фактическая диагностика

## Задача

Пользователь выбирает отправителя, управляемую группу и список согласившихся участников, задаёт предел попыток, интервал и необязательную цель подтверждённых добавлений. Сохранение черновика и просмотр страницы не должны приглашать людей. Явный запуск выполняет последовательные приглашения с видимым прогрессом; остановка и возобновление не повторяют уже обработанные/неизвестные результаты. Цель по числу участников не гарантирует, что Telegram разрешит добавления.

## Карта кода

- `manual-invite-campaign.js`: форма, валидация, quick-mode, состояние, polling и отображение причин.
- `scanner/manual_invite_campaign.py`: quick-draft/quick-start, разрешение username непосредственно перед обработкой, история, claim, единичный InviteToChannel, проверка членства, pause/stop.
- `scanner/operations.py`: аккаунты, общая очередь, общий outbound guard, resume, safe_rpc_metadata/invite_rpc_diagnosis и API.
- `scanner/owner_sender.py`: основной отправитель; нельзя смешивать с отдельной сессией secondary.
- `scanner/operation_workbench.py`: границы аккаунта, целей и согласия.
- `scanner/invite_progress.py`: подсчёт результатов.
- `scanner/{isolated_invite,isolated_contact_batch,isolated_invite_campaign,invite_run_budget}.py`: прежние конечные сценарии со специальными рамками. Не запускайте все контроллеры одновременно; часть исторических констант в этой копии заменена синтетическими. Эти модули не являются универсальной квотой Telegram.
- `scanner/spambot_check.py`: ограниченная диагностика официального бота. Ответ «ограничений нет» не доказывает успешность InviteToChannel.
- `scanner/tests/`, `tests/manual-invite-campaign.test.cjs`: unit/поведенческие проверки.

Объекты SQLite: op_accounts, op_jobs, op_items и settings manual_invite_campaign_job_*; активный ручной контроллер нельзя искать только по op_jobs.state. Журнал должен сохранять фазу, метод, безопасный RPC-код, время и outcome без телефонов, access_hash, auth_key и сырого request/exception текста.

## Наблюдавшиеся классы сбоев (без клиентских данных)

1. FLOOD_WAIT_X — Telegram требует паузу на X секунд. Истечение этой паузы само по себе не обещает успешность следующего приглашения.
2. PEER_FLOOD — получен непосредственно на InviteToChannel, в том числе в отдельной технической группе. Точного срока в самом ответе не было. Не следует объявлять это постоянным баном или «теневым баном группы» без доказательств.
3. UserNotMutualContactError и privacy/missing_invitees — ограничения конкретного приглашения. Нельзя распространять их на всех пользователей или считать взаимность универсальным требованием API.
4. Telegram вернул InvitedUsers без missing_invitees, но членство не подтвердилось. Такой результат нельзя считать успешным или молча повторять.
5. После окончания сохранённого FloodWait одна попытка основного отправителя закончилась BadRequestError. Поздняя проверка подтвердила отсутствие участника. Конкретное message потеряно общим except и не восстановилось из журнала. Нельзя приписывать этому случаю CHAT_MEMBER_ADD_FAILED без фактов.
6. Предварительная проверка большого списка задерживала реальные попытки и не давала понятного прогресса. Quick-mode уже существует: список разрешается по одному перед обработкой. Минимальная проверка отправителя/прав/членства нужна для корректного учёта, но не следует делать полный проход по всей базе перед первым инвайтом.

## Недавняя локальная правка

В общем except `ManualInviteCampaign.step`, если invitation уже заявлен, теперь добавляются `verification_error = invite_rpc_diagnosis(exc)` и `member_before`. Сохраняется прежний uncertain/stop/no-repeat. Безопасная metadata должна содержать SDK-класс, enum-код и конструктор метода; произвольный текст не сохраняется. `test_manual_rpc_regression.py` проверяет это на СИНТЕТИЧЕСКОМ CHAT_MEMBER_ADD_FAILED. Этот тест не раскрывает код потерянного реального ответа.

Требуется доработать: точное разделение фаз resolve/before-membership/invite/after-membership, известный отказ vs неизвестный результат; отрисовку сохранённой metadata; интеграционную приёмку. Не меняйте прошлую историю, чтобы сделать показатели красивее.

Официальная справка: https://core.telegram.org/method/channels.inviteToChannel , https://core.telegram.org/api/errors , https://telegram.org/faq_spam . Изучать с учётом установленного Telethon 1.40.0. Пакет не устанавливает квоту «50/100 в день» от имени Telegram.
