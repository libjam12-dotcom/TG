# Передача и границы доступа

Пакет создан положительным списком файлов исходников, а не архивированием рабочей папки. Нет .git, .env, client-access, файлов ключей, cookies, runtime-баз, резервных копий, .session, tdata, списков контактов, фотографий, скриншотов, исходных отчётов или deployment-реквизитов. Никакой доступ не выдавался, репозиторий не опубликован, сервер не обновлялся.

Сессия Telegram эквивалентна доступу к аккаунту. Не просите у владельца основные sessions/tdata/2FA/Cloud/SSH. Для сетевого теста используйте свой тестовый аккаунт; приглашать можно только согласившихся участников, сохраняя реальные ограничения Telegram. Ограничения не обходить сменой аккаунта/прокси, сбросом cooldown или историей.

Запуск по умолчанию изолирован loopback и новой локальной базой. Блокировка внешних Python-сокетов уменьшает вероятность случайного действия, но не ограничивает произвольный код/дочерний процесс или браузер: для недоверенного кода нужна отдельная VM/контейнер и сетевые правила ОС. В среде разработчика не должно быть владельческих ключей и mounted production volumes. Не вводите реальные секреты в unit-тесты.

Перед первым коммитом запустите `python dev/audit_package.py` и изучите находки. Скрипт ищет запрещённые файлы, ключи, токены, production-домен и личные локальные пути, выполняет синтаксическую проверку Python и проверяет symlinks. Он не передаёт содержимое файлов в сеть. Совпадения тестовых паролей и ложных credentials в негативных unit-тестах классифицированы отдельно: они не дают доступ к сервисам. Автоматическая проверка не является математической гарантией отсутствия неизвестного секрета.

Передаваемый архив содержит только папку chatcleaner-developer. Внешние private-*.json, build-скрипты, локальные журналы и таблица исходных значений из рабочего каталога в архив НЕ входят. MANIFEST.sha256 позволяет проверить состав; контрольная сумма ZIP поставляется отдельно. Manifest не является цифровой подписью и не защищает от подмены архива вместе с контрольной суммой.

До установки изменений: проверить patch, миграции, сетевые обращения, зависимости и обработку секретов; затем резервная копия и управляемое обновление владельцем. Никакой автоматической публикации/GitHub Actions/deploy keys в пакете нет. Отзыв доступа к будущему репозиторию не удаляет скачанную копию кода у разработчика.
